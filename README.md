# 多门交互导航 · 门扇中点推行

## 在 PyCharm 里运行

将这个目录作为 PyCharm 项目打开，解释器选择已有的 Anaconda **mujoco** 环境。打开 **run_demo.py**，右键选择 **Run 'run_demo'**，或者点击文件底部的绿色运行按钮。无需输入命令，也无需改工作目录。模型 XML 已放在工程内。

运行时会打开 MuJoCo 窗口和中文实时决策面板。面板自动跟随当前决策门。地图用两种颜色显示同次 A* 比较的经门和绕行候选，实线强调所选路线。代价区实时显示两条路线各自的剩余几何长度、机械功、等效米折算和到终点总代价，并显示门角、阻力、净收益 C 和动作原因。当前门的代价曲线会随重规划更新，下方保留整张地图各门的最新判断。点击 MuJoCo 窗口后按空格可暂停，再按一次继续。到达终点后窗口会停留供查看，关闭 MuJoCo 窗口即可退出。默认参数放在 run_demo.py 开头。

将 `MODE` 改成 `"detour"` 可以在同一张地图上观看全程走绕行口的对照。恢复 `"auto"` 即回到交互策略。

默认开启 `USE_MINIMUM_SNAP`。决策地图中的绿色细虚线显示当前正在跟踪的局部轨迹。将该项设为 `False` 可用同一地图、代价和接触控制对比原逐航点跟踪。

验证环境为 Python 3.9、MuJoCo 3.3.2、NumPy 2.0.2，并使用 Anaconda 环境自带的 Tk。项目已附带模型，无需新增依赖。

## 地图工况

门与门之间直接连通。各门的绕行口交替安排在门线两侧，全局 A* 可从当前门直接规划到下一扇门或绕行口。

| 门 | 设计目的 |
| --- | --- |
| D1 | 小初始开角，上方绕行口抬高。经门路线更短，计入预计推门功后仍选择绕行 |
| D2 | 大初始开角和反侧门轴，检查直接穿门 |
| D3 | 长绕行、易推门。传感层间歇去除近处的大部分门扇回波，墙面回波保留 |
| D4 | 门开始转动后铰链阻力快速上升，观察接触后更新预计功并改选绕行 |
| D5 | 门先转一段再遇到隐藏行程限位，观察加力对继续推门代价的影响 |
| D6 | 铰链静阻力较高，观察加力阶段的经济性切换 |
| D7 | 触碰后快速向开门方向甩开的轻门，由仿真弹性助力夹具产生 |
| D8 | 门完全关闭，两侧门轴在接触前难以区分，中点接触后根据实际运动消歧 |
| D9 | 起动力较高，门开始转动后阻力下降，验证加力成功后恢复普通推门 |

## 实现

- 全局 A* 在同一张有向动作图上比较经门、直接穿门和绕行。推门边的几何项包含接近段、机心推行段和脱离过门段。机械功用切向阻力估计乘以门扇中点的剩余推行弧长，再由 `EFFORT_WEIGHT_M_PER_J` 折算为等效米。退离后按剩余路程规划绕行。未来未观测的门用临时接近边表示，到门前依据实际观测再规划。
- 自由飞行在固定高度和航向上用分段七次 Minimum Snap 生成位置、速度和加速度参考。机体包络与预留余量进入凸走廊约束，曲线全段由 Bézier 控制点凸包约束。求解后检查速度、加速度、jerk 和基于高度保持的名义旋翼推力余量。动态量超限时增加时间并重新求解。退离后接入绕行时，优先按各段的动态上界调整时长，并在优化中约束沿段进度的偏差，减少长段内的近停顿。按段求解失败时回退到整窗统一放缩。位置、速度反馈和加速度前馈接入现有姿态内环。
- 局部规划只使用已经确认的动作航段。观测确认可直接穿门后，接近段可提前接上过门段。全局路线选择推门时，若所有门轴假设的准备位置足够接近，且接近航段对所有假设都通过净空检查，可提前规划到推门准备点。若首次比较后仍在飞向门前航点，接近该点时会用最新观测再比较一次，并尝试直接接入推门或绕行。运动中接入准备点或脱离后因起始状态求解失败时，几何航段的横向偏离可放宽到 0.55 m，墙和门扇仍受原净空约束。释放与退离先卸载、低速分离，再接入自由飞行轨迹。释放分离时把期望速度限制在 0.58 m/s 以下。推门后，满足分离和净空条件时，脱离目标可沿穿门方向前移、减少侧移，优先斜接到同一房间的下一段。直达门后点的航段贴近门扇尖端时，规划器可选取有净空的绕尖过渡点。放弃推门时，满足净空后将退离和绕行放入同一窗口，并尝试圆滑连接绕行口的进出口与来去航段。新轨迹优先接上仍有效的上一段位置、速度和加速度。净空变化、跟踪偏差变大或窗口需要续接时重求，失败时沿仍有效的轨迹减速，或使用核验过净空的制动轨迹。
- 门和墙按物理尺寸建模。过门时检查机体包络与原始墙面、门扇实体的间距。门扇自由端弦长用于初步净空筛选，实际脱离需要满足从当前机心出发的轨迹检查。测距拟合中的墙点过滤容差仅用于感知。
- 统一使用门扇中点作为接触目标。粗地图只提供两侧门框，测距分别评估两侧门轴假设。用 IMU 传播位置并由墙面测距校正，接近悬停时才用加速度计校正重力方向。清晰的门扇回波校正门角，门扇回波不足时，受载且机心运动符合绕轴约束才使用机心轨迹估角。长时间缺乏门扇观测会退出接触。
- 推门前各门共用默认切向阻力先验。接触后用短时受载窗口内的切向推力残差更新阻力估计。普通推门期望水平速度上限为 0.36 m/s。出现受载停滞时，若经门仍划算并具备有效接触和新鲜门角观测，则切换为加力。加力阶段以当前实测切向力的短窗中位数作为 (F_{mathrm{res}})，更新 (F_{mathrm{res}}Delta s) 并重新比较 A* 路线。经门净收益转负时退离绕行。确认门角前进后恢复普通推门，重新积累推行阻力样本。
- 切向施力目标按 `PUSH_FORCE_RAMP_N_PER_S` 抬升，默认 1.20 N/s。加力阶段以代价变化、门角进展或接触观测失效结束。飞控加速度和旋翼输出仍有限幅。若输出已限幅，实际接触力可能趋稳。此时若净收益仍为正，维持当前接触状态，面板会显示限幅。
- 物理门轴、阻力和关节角真值只参与场景构建和离线记录。D3 的回波丢失是传感扰动测试，D7 的快速甩开是场景夹具。离线结果包含估计门角相对于关节真值的误差和碰撞记录。

`runs/trace.jsonl` 保存逐帧估计、轨迹参考和状态，`runs/result.json` 保存决策事件、重规划耗时、跟踪误差、净空和旋翼指令统计。运行目录、缓存、报告及训练产物由工程目录下的 `.gitignore` 排除。

`run_demo.py` 中的 `WALL_SMOOTHING` 控制实验性的长沿墙段横向速度软惩罚，默认关闭。可用相同 `SEED` 和 `RANGE_NOISE_M` 分别跑开启和关闭的工况。`result.json` 的 `trajectory_quality` 默认记录规划扫描延迟、自由飞行真值跟踪误差、净空分位数、参考 jerk，以及各绕行口的沿墙用时、额外横向行程、进出口曲率和局部净空。额外横向行程为横向总行程减去横向净位移的绝对值。没有符合条件的沿墙样本时，该指标为 `null`。刻意推门的接触沿用独立的接触统计。
